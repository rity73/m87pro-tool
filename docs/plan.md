## 1. 역공학 분석 요약

### 1.1 실행 차단 원인
| 항목 | 결과 |
|---|---|
| Smart App Control | **켜짐(강제 모드)**: `VerifiedAndReputablePolicyState = 1` |
| `mui.dll` (UI 라이브러리, x86, 익스포트 2005개) | **서명 없음** → SAC가 차단 |
| `DeviceDriver.exe` (본체, x86 MFC) | **서명 없음**: DLL 문제를 고쳐도 exe 자체가 차단될 수 있음 |
| `mfc140u/msvcp140/vcruntime140.dll` | 서명 있음 (제조사 인증서) |
| 로컬에서 빌드한 서명 없는 Rust exe | **정상 실행됨** (직접 테스트함) |

결론: 원본을 고쳐 쓰는 방법은 없고, 직접 빌드한 대체 프로그램은 이 PC에서 문제없이 실행됩니다.
단, 인터넷에서 내려받은 서명 없는 exe는 SAC에 막히므로 **GitHub 배포판에는 서명(SignPath)이 꼭 필요**합니다.

### 1.2 원본 구조
- C++/MFC 앱에 hidapi(HID 통신)와 wxSQLite3(설정 DB `db\*_datav1.db`)를 내장
- 장치 설정은 `config.xml`, 키 배열(144키, `key_index`·`light_index`)은 `layouts/rgb-keyboard.xml`에 정의
- 펌웨어 업데이트 기능은 실제로 설치 파일 zip을 내려받아 실행하는 것뿐이고, 장치에 펌웨어를 쓰는 명령은 **없음**
- Bluetooth 모드에서는 원본도 설정 기능을 지원하지 않음

### 1.3 통신 경로 (확인됨)
| 연결 | VID/PID | 인터페이스 | 방식 |
|---|---|---|---|
| 유선 USB | 0C45:8006 | MI_00 | 65바이트 Feature Report. `04 18` 시작 → `04 CC … NN` 헤더 → 64B 데이터 × NN (`AA 55` 트레일러) → `04 02` 적용 |
| 2.4G 동글 | 0C45:FEFE | MI_03 | 33바이트 Output Report `00 CMD LEN IDX payload[28] CHK`. 응답 앞 3바이트가 그대로 돌아오면 성공(ACK) |

이 PC에는 현재 **2.4G 동글(PID FEFE)이 연결**되어 있습니다.

### 1.4 기능 목록과 프로토콜 대응
| 기능 | 유선 CMD | 동글 CMD | 확신도 |
|---|---|---|---|
| 조명 효과 (19가지 모드, 색상, 밝기 0–5, 속도 0–5, 방향) | 0x13 | 0x05 | 높음 |
| 키별 RGB (사용자 조명) | 0x23 | 0x14 | 높음 |
| 키 재배치: 기본 레이어 / Fn 레이어 | 0x11 / 0x27 | 0x10 / 0x12 | 높음 |
| 하드웨어 매크로 | 0x15 | 0x09 | 중간 (헤더 일부 미확인) |
| 시스템: Win·Alt+Tab·Alt+F4 잠금, 절전 시간, 키 응답 시간 | 0x17 | 0x07 | 중간 (값 인코딩 일부 미확인) |
| 실시간 조명 / 음악 리듬 | 0x20 | 0x0B | 낮음~중간 |
| 배터리 잔량 | — | 0x20 | 높음 |
| 공장 초기화 / 키 초기화 | — | 0x0F / 0x1F | 추정 |
| PC 쪽 동작 (프로그램 실행, URL 열기, 텍스트 입력) | 키보드가 벤더 인터페이스로 `05 A6 ID`를 보내면 PC 프로그램이 실행 | | 중간 |

**중요:** 장치에서 현재 설정을 읽어 오는 명령은 없습니다(LED 프레임 읽기만 있음). 원본처럼 PC 쪽에 설정 상태를 저장해 두어야 합니다.

## 2. 개발 계획

### 2.1 기술 스택
| 영역 | 선택 | 이유 |
|---|---|---|
| 언어 | Rust (설치됨: 1.99.1, MSVC) | 단일 exe, 런타임 불필요 |
| TUI | `ratatui` + `crossterm` | 마우스(클릭·스크롤·드래그) 지원, Windows Terminal/conhost 모두 동작 |
| HID | `hidapi` crate, `windows-native` 백엔드 | C 컴파일 없이 순수 Rust, 원본과 같은 API 사용 |
| 설정 저장 | TOML 파일: `%APPDATA%\m87pro-tool\` | SQLite 불필요. 사람이 읽고 백업 가능 |
| CLI | `clap` (같은 exe 안에 포함) | 스크립트 자동화와 프로토콜 테스트에 사용 |

### 2.2 프로젝트 구조 (Cargo workspace)
```
m87pro-tool/
├─ crates/
│  ├─ m87-proto/   # 패킷 인코딩·디코딩 (순수 로직, 단위 테스트 100%)
│  ├─ m87-hid/     # 장치 탐색, 유선·동글 전송 계층, 재시도, ACK
│  └─ m87-app/     # 상태·프로필 저장 + TUI + CLI → m87.exe
├─ assets/layout.toml  # rgb-keyboard.xml에서 변환한 87키 배열
└─ docs/
```

### 2.3 화면 구성 (영어 전용, 짧고 분명한 표현)
- 상단 탭: **Lighting · Per-Key Color · Key Mapping · Macros · Settings · Device**
- 가운데에 키보드 그림을 표시하고, 마우스로 키를 클릭해 선택(키별 색상, 키 재배치)
- 원본의 모호한 이름 정리: 예) "Following Currents" → `Flowing`, "Fn Switch Function" → `Fn key behavior: Hold / Toggle`
- 하단 상태 줄: 연결 방식(USB / 2.4 GHz), 배터리, 마지막 전송 결과 (`Applied` / `No response from keyboard`)
- 모든 쓰기 동작은 `Apply` 버튼으로 명시적으로 실행. 초기화 같은 위험한 동작은 확인 창을 띄움

### 2.4 단계별 범위
| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **M1** 기반 | workspace, proto 인코더와 단위 테스트, 장치 탐색, CLI `m87 devices`, `m87 battery` | 동글에서 배터리 값을 읽음 |
| **M2** 조명 | 조명 모드·색상·밝기·속도·방향, 키별 RGB. CLI와 TUI | 키보드에서 눈으로 확인 |
| **M3** 키·매크로 | 키 재배치(기본/Fn), 매크로 편집기, 시스템 설정 | 키 입력으로 확인 |
| **M4** 마무리 | 프로필 저장·불러오기·내보내기, 초기화, 오류 메시지 정리 | 로컬에서 전체 기능 사용 가능 |
| *이후* | 음악 리듬, 실시간 조명, PC 쪽 동작(상주 모드), 유선 USB 검증, GitHub Actions + MSI(cargo-wix) + SignPath | 이번 범위 아님 |

### 2.5 미확인 항목 검증 방법
- 절전 시간·키 응답 시간·방향 값 인코딩, 매크로 헤더: **위험도가 낮은 명령부터** 실제 키보드에 보내 보고 동작을 관찰
- 펌웨어 쓰기 명령은 사용하지 않으므로 장치가 벽돌이 될 위험은 낮음. 최악의 경우 공장 초기화(Fn 조합 또는 0x0F)로 복구
- 각 단계를 시작하기 전에 키보드에 쓰는 명령 목록을 먼저 보여 드리고 진행

## 3. 리소스 사용량 검토와 대안

### 3.1 원본과 대체 프로그램 비교 (추정치)
| 항목 | 원본 | Rust TUI (계획) |
|---|---|---|
| 설치 크기 | 약 13 MB (exe 1.7 + MFC 4.8 + mui 0.8 + 스킨·폰트 약 5) | **exe 하나, 약 1.5–3 MB** (LTO, strip) |
| 메모리 | 약 50–100 MB (MFC, GDI+, 1 MB 배경 이미지) | **약 5–10 MB** |
| 대기 중 CPU | 상주 + 15초 간격 배터리 확인 | 이벤트 기반, 입력이 없으면 약 0% (배터리는 화면이 열려 있을 때만 확인) |
| 의존성 | VC++ 런타임 DLL, SQLite | 없음 (정적 CRT) |
| 실행 차단 | 서명 없음 → SAC가 차단 | 로컬 빌드는 실행됨. 배포판은 SignPath로 서명 |

### 3.2 검토한 대안
| 대안 | 평가 |
|---|---|
| Smart App Control 끄기 | 개발이 필요 없지만 시스템 전체의 보안이 낮아짐 → **권장하지 않음** |
| 원본 바이너리를 패치하거나 직접 서명 | SAC는 자체 서명 인증서를 신뢰하지 않음 → 불가 |
| Rust GUI (egui, Slint) | 메모리 30–80 MB → 요구 사항(가벼운 TUI)과 맞지 않음 |
| Tauri / WebView2 | 메모리 100 MB 이상 → 제외 |
| **Rust TUI + CLI** | 가장 가볍고, 마우스를 지원하며, 자동화도 가능 → **채택** |

### 3.3 이후 배포 고려 사항 (이번 범위 아님)
- GitHub Actions에서 `x86_64-pc-windows-msvc`로 빌드 → `cargo-wix`로 MSI 생성 → SignPath(오픈소스용 SignPath Foundation)로 exe와 msi 모두 서명
- SignPath Foundation은 공개 저장소와 OSI 라이선스가 필요함 → 저장소 공개 여부와 라이선스(MIT/Apache-2.0)를 미리 정해야 함
- 지금은 바이너리 이름, 버전 정보 리소스(`winres`), 정적 CRT 설정만 미리 해 둠
